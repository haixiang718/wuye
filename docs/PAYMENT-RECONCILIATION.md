# 支付入账检查与微信日账单核对

日期：2026-11-08。当前为管理员本机只读工具，**尚未接入后台菜单或自动任务**。它不调用微信下单、查单、关单或退款，不补写流水、不改账单、不发通知。

## 已实现

- 本地订单与账单明细、缴费流水、收据及收据明细逐项核对；金额按整数分计算。
- 同时检查费用缴费截止日期已推进、账单实收至少包含已入账在线支付、已支付费用不再被订单占用。
- 检查多项目订单的金额、费用和起止时间，避免仅合计相等掩盖分项错误。
- 微信 ALL 日交易账单与本地订单核对，报告漏入账、金额或交易号不一致、退款待核查等情况。
- 兼容原始 UTF-8/BOM、GB18030、反引号和末尾逗号格式；校验汇总单数及原订单总金额，拒绝不完整文件、错商户、错日期、非人民币、非法金额、重复成功交易和 SUCCESS/REFUND 单独导出。
- 报告提供中文 HTML、差异 CSV、完整 JSON。HTML 转义并禁用脚本，CSV 防止历史字段被当成 Excel 公式。

## 本地入账检查

启动项目专用 MySQL 后在项目根目录执行，商户号换成实际商户号：

```powershell
python scripts/payment_reconciliation.py local --date 2026-11-06 --app-id wx284821c708738ea9 --mch-id 1234567890
```

连接固定为本机 `127.0.0.1:13306` 的 `TT`，不接受远程库、表名或任意 SQL 参数。订单及相关表在同一个 MySQL 只读一致性事务中查询，按北京时间筛选本地入账日期。不会读取业主姓名、手机号、身份证、OpenID 或微信支付密钥。

本地检查不是微信官方对账；即使没有差异，`providerReconciled` 仍为 `false`。没有订单的日期只代表本次没有可检查的已入账订单。

## 微信日账单核对

1. 有权限的财务人员在微信支付商户平台找到交易账单/账单下载，选择已完成结算的交易日，下载**全部交易 ALL 原始 CSV**。SUCCESS 导出会遗漏退款，REFUND 导出会遗漏成功交易，工具会拒绝这两种专用格式。
2. 保留原文件，不用 Excel 重新保存，不改交易号、金额、表头或汇总行。放到项目 `.runtime/payments/bills/` 等受控私有目录，不能加入 GitHub。
3. 执行以下命令，替换商户号、日期和文件路径：

```powershell
python scripts/payment_reconciliation.py bill --date 2026-11-06 --app-id wx284821c708738ea9 --mch-id 1234567890 --file .runtime/payments/bills/2026-11-06.csv
```

工具要求 ALL 特有退款字段以及原订单金额，不能用应结金额、优惠后金额或手续费后的净额代替订单应付总额。同商户其他 AppID 的记录会排除并记录数量；本系统多小区使用同一商户和 AppID 时共同核对，完整结果仅供具有全公司财务权限的管理员使用。

文件内订单按订单号查询，不限制本地下单或入账日期，因此旧订单、跨日回调和补偿入账仍能匹配。另查询本地当天入账的订单；微信文件里没有的订单标记为 `LOCAL_ONLY_CHECK_TRADE_DATE`，需要核对相邻日期，**不直接认定资金丢失**。

## 输出与处置

每次建立新的 `.runtime/payments/reconciliation/<UTC时间>-<随机标识>/` 目录，不覆盖原报告：

| 文件 | 用途 |
| --- | --- |
| `report.html` | 双击打开的中文核对报告及核查步骤 |
| `differences.csv` | 差异类型、订单号、预期/实际值和中文说明 |
| `report.json` | 机器可读结果、来源摘要和限制 |

控制台仅输出计数、范围和结果目录，不显示订单/交易编号或业务资料。完整报告包含内部订单号，仅限有权人员；Windows 文件沿用用户目录权限，未额外创建独立 ACL 或加密副本。

返回码 `0` 表示本次范围无差异，`1` 表示有待核查项，`2` 表示输入或执行未完成。退款、撤销或未知交易状态均要求核查，不能显示为支付核对通过。

遇到“微信已收款、本地未入账”时，先核对签名查单、回调及补偿任务，不能要求业主再次付款。其他金额、收据或周期差异应保留原始记录并交财务处理，不能凭此报告直接改库。原始 CSV 的来源仍由财务确认，SHA-256 只证明本次使用了哪份文件，不是微信签名。

## 限制和后续工作

- 输入上限 32 MiB、5000 明细，本地结果上限 10000 订单，超限整体拒绝，不以部分结果冒充全量核对。
- 校验汇总行的明细数和原订单总金额（含同商户其他 AppID）；尚未核对手续费、优惠、净结算、银行到账及退款账务，不能作为银行资金结算对账工具。
- 当前使用既有流水/收据备注的精确订单引用，兼容纯订单号和“微信账单支付＋订单号”，不使用模糊包含匹配；后续后台任务应引入明确的财务关联模型。
- 账单实收只检查不低于已知在线支付金额，不能据此证明手工收款、其他渠道或实收超额全部正确。
- 暂不支持服务商/子商户账单、不自动下载账单、不提供财务差异审批和修复；生产查询须改用经过授权的受限账号和目标环境配置。
