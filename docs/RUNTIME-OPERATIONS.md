# 当前联调环境的检查与备份

工具固定使用本项目独立 MySQL `127.0.0.1:13306`，只允许备份 `TT` 和 `hc_community`。它不会启动服务、开启自动任务、发送公众号通知或调用支付，不适用于远程生产数据库。

## 检查运行环境

在项目根目录执行：

```powershell
python scripts/runtime_ops.py health
```

检查六个合并模式 Java 应用、中间件、管理端、H5 和网关端口，读取管理页/H5/网关/注册中心，执行 `SELECT 1`、Redis PING，并核对隧道守护进程与记录中的定时任务关闭参数。报告仅含名称、端口、状态，不输出进程命令行、密码或业务数据。

退出码：`0` 表示列出的本机检查通过；`1` 表示至少一项检查未通过；`2` 表示工具未能完成。端口或页面正常不等于房产权限、公众号送达、真实支付、外网隧道或整套业务验收通过。定时任务项核对的是本地启动记录，不能作为任意外部 Java 进程的运行配置证明。

## 创建并核验备份

```powershell
python scripts/runtime_ops.py backup
python scripts/runtime_ops.py verify .runtime/backups/operations/TT-时间-随机标识
```

`backup` 分别生成两个数据库的全量结构与数据备份，包括数据库中存在的触发器、存储过程和事件。工具要求基表为 InnoDB，使用 `--single-transaction`；两个数据库分别建立快照，因此不承诺跨库同一时点。业务跨库写入或数据库结构升级期间，应先安排停写窗口，再做计划备份。

备份保存在 Git 忽略的 `.runtime/backups/operations/`，每个数据库独立目录包含：

- `database.sql`：完整私有 SQL，可能包含 AppSecret、业主资料等敏感信息，不能上传 GitHub 或公开共享。
- `manifest.json`：版本、数据库、完成标记、文件大小、SHA-256、表清单与每表行数。
- `restore-drill-*.json`：执行隔离恢复演练后写入的结果，不含表内数据。

只有导出进程成功、文件非空、存在 MySQL 完成标记、提取到表结构，并核验摘要后才形成完成清单。中断或失败的 `.partial` 文件不会被当作有效备份。`verify` 会重新校验大小、摘要、完成标记和表/行数清单；校验失败返回非零。

MySQL 连接参数通过临时私有选项文件传递，进程参数中不放密码，不继承 `MYSQL_PWD` 或用户的登录路径文件。当前本地隔离 root 无密码，应用账号 `wuye_local` 的密码不会被误作 root 密码。工具不修改数据库账号。临时选项文件在操作结束时移除；备份文件沿用本机用户目录的权限，尚不提供备份加密或异地副本。

## 隔离恢复演练

```powershell
python scripts/runtime_ops.py restore-drill .runtime/backups/operations/TT-时间-随机标识
```

工具先验证备份，然后自行生成 `ops_restore_` 加 12 位小写十六进制字符的随机库名。它不提供恢复覆盖 `TT` 或 `hc_community` 的参数，也不会删除已存在的同名库。

恢复前拒绝含 `USE`、`CREATE DATABASE`、客户端命令、视图/触发器/存储过程/事件等可执行对象的 SQL；这些对象仍保存在完整备份内，但需要单独审查恢复，不能通过这个受限演练直接导入。请仅使用本工具生成并保存在本机的可信备份；SHA-256 是完整性检查，不是备份来源的数字签名。

恢复成功后比较表集合与每表精确行数。行数来自导出事务中的单行 INSERT 计数，而不是导出完成后重新读取可能已经变化的业务表。演练结束只删除本次成功创建的随机库，源业务库不改动。演练失败也会尝试删除该随机库，并保留结果；若清理失败，命令返回非零，需要核对报告及随机库状态后处理。

没有“覆盖正式库”的自动恢复命令。真正灾难恢复需要停写、核对备份时间和版本、保留之后产生的收费流水，再由运维按恢复方案执行，不能把旧快照直接覆盖已有新账务的数据库。

## 后续生产运维

本轮工具不自动安装计划任务，不自动删除历史备份，也没有异地上传。正式上线前还需确定备份频率、保留周期、加密及异地存储，完成生产环境恢复演练，并配置监控告警。Redis 中的通知锁/进度、Kafka 数据及业务上传文件也需要独立持久化和恢复方案；数据库备份不包含它们。本机运行配置和 SSH/公众号密钥应由管理员另行受控备份，不能放进可分享的部署包。

## 本机验证记录（2026-11-03）

14 项定向测试通过，覆盖不完整/失败备份、摘要损坏、清单路径逃逸、非事务表、错误恢复目标、已有目标不删除、恢复行数不一致及异常输出脱敏。实际命令行损坏备份检查返回 `2`，注入的敏感标记未出现在输出。当前本机 21 项健康检查通过。

已完成两个数据库的真实全量备份及随机库恢复：`TT` 327 张表、215303 行，`hc_community` 65 张表、19769 行，恢复后的表集合和逐表行数与备份一致。演练库均已删除，查询确认没有残留 `ops_restore_*` 库。第一次逐行自动提交导入较慢，主动取消该次隔离演练并完成清理后，改为每表事务重新备份和演练通过；失败记录与原备份保留，没有覆盖源业务库。

机器可读的本机证据保存在 `.runtime/operations-results.json`，完整备份保存在 `.runtime/backups/operations/`。这不等同生产环境恢复、跨库一致快照或异地灾备已完成。
