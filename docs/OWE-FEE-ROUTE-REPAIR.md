# 欠费缴费接口注册修复（2026-11-03）

## 问题与原因

后台房屋收费的“欠费缴费 → 确定收费”调用 `fee.payOweFee`，本地返回 HTTP 401：`AppId 没有权限访问 serviceCode = fee.payOweFee`。

0.8 源码包含 `PayOweFeeListener`，但项目附带的旧 0.6 数据库缺少这个服务的注册及后台应用授权。请求在业务执行前被拒绝，与微信公众号权限无关。

## 修改

在 `scripts/local-routes.json` 添加服务 `local_20261103_001`，仅向后台应用 `8000418004` 授权。该监听器将缴费明细及费用更新交给订单事务服务，因此配置为 `Y`、`POST`、`http://order-service/orderApi/service`，与既有 `fee.payFee` 的调用方式一致。未给 H5 应用增加人工收费权限。

通过原有 `python scripts/local.py migrate` 应用，并刷新 `APP_ROUTE_SERVICE` 缓存。配置纳入初始化迁移，后续启动或部署仍可复用；上线前应在目标数据库备份后执行。

## 本地验证

- 用已登录的真实后台会话提交缺少 `fees` 的请求：修复前 HTTP 401，修复后 HTTP 400“请求报文中未包含费用信息”，证明请求已进入监听器的参数校验。
- 创建唯一 `OWE` 前缀的独立房屋、业主、收费项目和 0.01 元一次性费用，从浏览器实际操作欠费缴费并选择现金，返回 HTTP 200、业务码 0，无页面脚本错误。
- 核对 `pay_fee_detail` 实收/应收金额均为 0.01，支付方式为现金；`pay_fee` 状态变为 `2009001`（缴费结束），收费截止时间更新。
- 测试数据已清理，14 张业务表的内容哈希恢复到测试前。订单审计记录保留。未提交 BIND201 的电费、公摊费，未调用微信支付或发送通知。
- 本地启动器 14 项单元测试通过。
- 重复执行迁移后 `c_service`、`c_route` 内容不变，确认幂等且有效授权仅包含后台应用；最终再次核对原有 8 张财务表与修复前完全一致。

修改前整库备份及浏览器响应、数据库核对结果位于忽略目录 `.runtime/backups/owe-payment/`、`.runtime/owe-payment/`，不提交凭据或业务数据。

## 验证边界

这里的“收费”是工作人员登记已收到的线下款项，不会自动扣取业主微信余额，也不代表已接入在线支付。

独立测试还确认，原 `PayOweFeeListener` 的收据保存代码被注释，收费响应的 `data` 是空数组。收款明细和缴费状态可以正常保存，但此路径的收据生成、打印尚未恢复；本次接口配置修复不改变收据事务逻辑。未据此宣称完整会计入账、在线支付或重试幂等性已验证。
