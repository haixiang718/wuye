## 发现的问题及优先级

### P1：公开注册被鉴权挡住

`POST /app/owner.ownerRegister` 实际返回 401。`ApiSMOImpl.java:93` 清理客户端身份头后，仅在服务端已有用户时填回用户身份；匿名注册缺少后端 API 所需的默认用户 `-1`。公开注册白名单存在，但不能解决这段转发的身份缺失。

建议修复服务端公开入口转发：仅对白名单匿名业务设置明确的匿名身份，继续拒绝客户端伪造身份。应补真实 front → API 集成回归，不能只依赖替身单测。

### P1：账单人工审核发布没有形成门槛

测试中在没有任何账单时，`fee.listFee` 和编译 H5 已显示该收费项目。现有页面主要读取费用，尚不满足“后台产生账单 → 人工审核发布 → 业主看到可缴账单”的目标。

收费项目与已发布账单需要明确区分，新增审核发布状态并由查询、通知及支付接口共同校验；仅增加按钮不能完成这项约束。本次支付处于禁用状态，未实际验证未审核费用能否下单。

### P1：H5 欠费缴费页运行报错

`wuye-xcx2/WechatOwnerService-v0.8/pages/roomOweFee/roomOweFee.vue:148` 调用未定义的 `_loadRoomFee()`。实际编译页面加载时捕获 1 条对应 JS 异常；普通房屋费用详情页面没有该错误。

### P0：支付上线前必须修复的回调问题

本节是**遗留 V2 回调适配器的隔离诊断**，没有连接真实微信支付，也不是已完成 V3 接入。6 个失败检查对应 5 类问题：

| 问题 | 动态证据 | 影响与限制 |
| --- | --- | --- |
| 回调入口未传入 wId | 单笔、欠费两个 XML 入口均接收 URL 参数 wId，但解析后未传给 map 方法；下游确认均为 0 次 | 正常格式回调无法进入确认；两个失败案例是同一根因 |
| 适配器没有核对支付金额 | 合成应付 100 分场景，签名合法的 1 分回调仍转发确认 | 适配器未读取应付订单金额，未将实付金额传给确认接口。未验证下游是否另有防护，不能宣称已复现真实少付入账 |
| 未核对 appId / 商户号 | 与所选合成配置不一致、但使用测试密钥正确签名的回调仍转发 | 说明适配器未校验配置归属；不是密钥泄露或真实伪造支付的证明 |
| 下游业务失败仍应答成功 | 下游 HTTP 200、body code=1，单笔适配器仍返回成功 | 只按 HTTP 状态处理，可能让支付平台停止重试 |
| 欠费确认失败后缓存被提前消费 | 首次下游 HTTP 500；再次回调没有再次调用记账接口却返回成功 | `getAndRemoveValue` 先移除订单；失败没有恢复，重试被误判为已处理 |

错误签名拒绝检查通过。手工在 map 参数提供 wId 后，正常合成数据可到达模拟下游，这仅用于隔离入口故障。

另外，重复单笔 map 回调被转发 2 次；**下游记账幂等性没有验证，不能据此断言发生重复入账。** 后续需要用持久化支付订单、金额与商户归属核对、事务记账及幂等控制，覆盖重复通知、失败重试、销账、流水、主动查单和对账。

## 重跑方法

先启动现有 merged 本地服务与管理后台，保持短信和自动任务关闭，并准备本机已有测试号小区配置及管理员浏览器会话。不要并行运行 Java 验证，它们共用 `.runtime/billing-audit`。

```powershell
python scripts/simulation/billing_flow.py prepare
node scripts/simulation/browser_flow.cjs approve
node scripts/simulation/browser_flow.cjs before-bill
python scripts/simulation/billing_flow.py generate
node scripts/simulation/browser_flow.cjs after-bill
python scripts/simulation/run_linked_notification.py
node scripts/simulation/browser_flow.cjs after-notice
python scripts/simulation/run_payment_audit.py
python scripts/simulation/billing_flow.py final_state
python scripts/simulation/billing_flow.py cleanup
```

诊断脚本会保存失败检查；浏览器或支付诊断进程正常退出，不表示所有检查通过，必须阅读 JSON 的 `checks`。浏览器脚本现还记录 `completed` 和脱敏异常类型，执行中断不得标记通过（本轮业务运行结果来自该字段增加前的完整执行，保留原始记录）。任何中断都应检查私有资料记录并执行 cleanup；不要反复注册或删除不属于本次随机标识的数据。H5 预览和临时网关由浏览器脚本启动并在结束时关闭。

交付前独立只读审查发现并修正了诊断脚本“空检查或中途异常可能记录 passed=true”的问题；已用无网络、无数据库的启动失败注入验证，异常现在记录未完成、失败和退出码 2。生产业务缺陷仍按上文记录，未在本轮顺带修改。

建议先修复注册、审核发布和欠费页，再完成支付订单与记账的可靠处理，最后在微信商户与域名就绪后执行真实小额支付、到账、退款和对账验收。
