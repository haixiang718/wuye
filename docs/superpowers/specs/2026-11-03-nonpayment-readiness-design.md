# 非支付流程完善

用户已要求先完善商户号之外的工作。本轮沿用已确认的收费业务方案及固定域名联调架构，不重新切换公众号、不迁移运行中的业务数据库到 2GB 服务器。

## 范围与取舍

先完成可独立验证的三部分：业主 H5 与非支付业务验收、当前运行环境备份及健康检查、可审查的 Linux 发布制品。相比仅整理清单，这些交付可直接用于后续上线；相比立即整套上云，不会超出现有服务器资源和已批准的入口部署范围。

1. H5：检查注册及审批绑定、已有业主登录、多房产切换、指定房屋账单、无权限和登录过期反馈；支付保持不可用且说明原因。保留服务端归属校验，不能用前端隐藏代替授权。发现缺陷时先复现并补回归，再最小修复。
2. 通知与出账：只读核对正式号实际模板；有可用模板时准备字段映射，没有时记录外部阻塞。未经指定收件人，不外发通知。出账仍为生成草稿、人工审核发布、人工推送；不擅定账期，不启动历史定时任务。
3. 运维：给当前环境提供不泄密的健康报告及完整数据库备份，备份带完成校验、摘要和恢复说明；恢复演练只用随机隔离数据库。生产密钥不进入代码、分享报告或发布包。
4. 发布：制作六 Java、后台、H5、受限业主网关的 Linux 发布准备工具，含清单、校验、生产配置模板、启停守护和安装说明。此交付不等于已经在 Linux 验收业务；真正切换需资源、生产配置和全流程演练就绪。

## 验收与限制

独立测试、真实本地业务调用、实际微信手机验收分别记录，不相互替代。使用标记测试资料，写入前备份、测试后清理并验证。真实支付及对账、关单、退款等依赖商户号的事项继续关闭。新模板权限、客户正式资料、账期和生产资源仍需客户提供，记录为外部条件而非已完成。

当前已有菜单点击、正式号登录和已有房屋/账单查询的用户手机验收，可作为基线；新用户、多房产及正式号通知仍需另外验收。
