# 员工收费逐笔明细

用户要求把按员工累计的金额拆开，并显示对应收费时间。

采用每个 `pay_fee_detail.detail_id` 一行的明细方式，同一收费操作中的多个收费项目分别显示；每行保留流水编号，便于核对。页面显示收费时间（秒）、收费员工及编码、收费对象、收费项目、支付方式、应收、实收、收费流水。按收费时间及流水编号倒序排列。

沿用已有员工编码、小区及日期筛选。日期按收费明细实际创建时间筛选，结束日期包含当天。不指定日期时逐笔展示全部符合权限条件的历史记录。页面说明统计口径，不把历史数据重新合并为一行。

复用 `api.getStaffFee` 和既有后台权限。查询以收费明细为主，员工归属通过订单关联，保留商户归属限制。使用平面 JOIN 以兼容现有 ShardingSphere 路由；按收费明细及显示字段去重，金额直接取原明细，不做累计。支付字典有重复条目时只取一个名称，计数使用 `COUNT(DISTINCT detail_id)`，避免员工关系和字典重复造成重复显示。列表和总条数共享同样的筛选条件。

修复后台分页条数、前端总页数计算。原空导出按钮改为“导出本页”，输出当前页的逐笔 CSV，保留时间和流水。

SQL 配置修改前整库备份，仅替换该接口查询模板并刷新 SERVICE_SQL 缓存；收费、账单和账户表保持原样。不重新生成收费记录。

验证包括：同员工两次收款保持两行、同笔多费用保持独立流水、收费时间、日期边界、分页、空结果、商户及小区隔离、关联去重、导出，以及真实浏览器页面。

本地数据库更新命令为 `python scripts/migrate_staff_fee.py --apply`，仅允许回环地址 13306 的 TT 或隔离测试库。执行前整库备份，并刷新查询缓存；收费记录不受迁移影响。服务包需要包含 `ListStaffFeeSMOImpl` 的分页修正，前端使用配套的员工收费页面。
