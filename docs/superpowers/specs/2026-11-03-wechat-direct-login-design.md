# 微信直接登录与房产验证绑定

用户明确要求省去注册、账号密码登录，并确认：姓名、手机号、身份证号与后台已有资料完全匹配后立即绑定，不再人工审核。

## 交互和权限

微信内首次进入 H5 自动发起正式公众号 OAuth，授权后建立微信身份会话。无房产绑定时可进入首页及个人中心，房屋和账单区域显示绑定入口，不显示任何业主资料。不要求用户设置账号或密码。已有正式号绑定自动识别，打开原账单链接仍由后端校验房产归属。

采用微信身份与房产访问权限分离：未绑定身份只持有服务端签发的短期不透明微信身份凭据，不赋予普通业主访问权限；绑定成功后才签发原系统可复用的业主会话。技术用户记录由服务端按需建立，用户无需注册。对比直接伪造 ownerId 或仅在前端隐藏数据，此方案沿用原后端房产权限；对比将全部未绑定用户当普通业主，也不扩大旧接口权限。

绑定页仅要求姓名、手机号、身份证号。本轮正式号只关联一个小区，小区由服务端公众号配置确定，不提供多小区选择界面；跨小区选择留待后续扩展。三项与同一条有效业主资料精确匹配才建立正式号微信绑定，立即可访问该业主所属房屋及已发布账单。匹配不到、存在歧义、资料缺失都不新建房屋或真实业主，统一提示资料不匹配，请联系物业。姓名首尾空白、手机号首尾空白、身份证尾号 x/X 可规范化，其余内容不得模糊匹配。

一人多房：同一业主记录的多个房屋自动出现在列表；本小区不同业主记录需要分别验证绑定，不凭同名或手机号放开其他资料。返回已核验的 owners 列表，新绑定后默认选中新记录，房屋页支持切换；通知链接按 roomId 在已核验记录中定位。已有绑定保留；被拒绝或待审的历史绑定不因微信登录自动放行，只能通过本次三项验证规则新建/更新自身对应绑定。跨微信身份不得抢占、移动或覆盖其他用户已有关系。

## 接口约定

- 沿用 OAuth state、短期单次 authTicket 交换；URL 不出现 OpenID、用户 key、token 或身份证。
- 无房产时的交换结果为 `code:0, hasBinding:false, wechatSession:<opaque>, expiresIn:<seconds>, owner:null`，不返回业主 token；H5 保存微信身份状态，不能把它写入 OWNER_INFO 冒充房产。
- 已绑定时保留现有 `owner, token` 响应，并增加 `hasBinding:true` 与 `wechatSession`，用于新增绑定。
- 新增 `POST /app/bindOwnerWechat`，接受 `wechatSession,name,phone,idCard`，可含已校验小区标识；服务端从微信会话确定 AppID/OpenID，不采信浏览器传入身份或 userId/ownerId/state。
- 成功返回业主登录结果；绑定请求要防重复和并发，匹配失败要限制尝试频率，不能返回具体哪个字段命中或泄露候选资料。日志不打印凭据和个人信息。

原账号密码接口不扩权，旧小程序行为保留。H5 移除注册、密码登录的产品入口，旧链接引导至微信授权/绑定。电脑非微信浏览器显示“请在微信中打开”，本机开发预览不模拟真实微信授权。

## 验证和运行

先做后端与 H5 回归，覆盖未绑定、精确匹配、任一字段错误、重复、并发、凭据过期、冒用身份、历史绑定保留、多房屋及已发布账单隔离。使用合成身份或本地标记资料，真实公众号手机首次授权须另验；不擅自发送微信消息。重新构建 H5、必要的 Java 服务，保留运行制品回退备份。支付和定时任务继续关闭，其他历史未提交修改不纳入本轮。
