# 正式服务号账单订阅通知接入设计

日期：2026-10-26。状态：待用户确认设计；尚未实施。

## 目标与验收边界

在既有物业后台单笔“推送账单”入口中支持微信新版订阅通知，在现有业主 H5 中接入微信官方订阅授权组件。继续复用业主、房屋、账单和后台员工权限体系。

服务精简实验继续暂停。此次不迁移业务服务、不启用定时群发、不发布菜单、不创建支付订单、不发送真实通知，也不自动覆盖当前测试号配置。正式公众号切换和手机收件验收在环境条件齐备后单独执行。

当前没有域名，因此本轮可以完成代码、离线接口验证、页面构建和本地集成验证；不能把这些结果写成正式公众号订阅、通知收件和卡片跳转已经跑通。

## 已核实的微信能力

- 正式账号为已认证服务号；凭据只保存在忽略的 `.runtime` 文件中。
- 当前私有模板为“物业费缴费通知”，公共模板编号 2470；实际模板 ID 由配置读取，不写死在业务代码。
- 模板字段固定为 `thing1` 小区名称、`thing2` 单元房号、`thing3` 缴费类型、`amount4` 缴费金额、`time18` 缴费截止日。
- 模板 `type=2` 是一次性订阅，用户一次同意允许一次对应通知；不承诺一次同意后每月自动发送。
- 服务端发送入口为 `POST /cgi-bin/message/subscribe/bizsend`。明确成功为 HTTP 成功且 JSON `errcode=0`；新版示例不含 `msgid`，不能沿用旧版必须包含消息 ID 的判定。
- H5 采用 `wx-open-subscribe` 开放标签，加载官方 JS-SDK 并通过服务端签名初始化；不使用小程序的 `wx.requestSubscribeMessage`。
- H5 订阅组件要求服务号已配置 JS 接口安全域名；网页授权域名是另一项配置，两项都需按实际入口填写。
- 微信可通过 `subscribe_msg_popup_event`、`subscribe_msg_change_event`、`subscribe_msg_sent_event` 回调订阅行为与异步发送结果。

## 方案比较与选择

1. **推荐：按公众号配置选择新旧协议，共用原账单推送入口。** 旧测试号保留旧版模板消息；正式号启用订阅通知。新增官方授权组件、服务端签名、回调记录和错误提示。改动集中，便于回归和切换。
2. 全量替换旧版模板消息。代码分支较少，但会破坏原测试号验证路径，且可能误用已有模板 ID。
3. 把订阅和发送另放在本机 Node 网关。开发较快，但形成另一份凭据、权限和发送状态逻辑，后续部署与核查困难。

采用方案 1。原 Node 网关只增加精确的路由及校验文件转发，不承担权威订阅状态或通知发送业务。

## 后台发送设计

- 保留 `/app/fee.pushBill` 参数、物业员工鉴权、小区归属、指定当前账单和待缴金额校验。
- 公众号增加明确的账单通知协议配置：缺省为旧版；订阅通知须显式配置。沿用现有欠费模板 ID 属性，不能按模板 ID 的外观猜协议。
- 账号属性使用现有属性机制，新增配置编码必须避开已有 `33001` 至 `33016` 及其他已占用值，并在本地迁移脚本中幂等注册展示名称和值。
- 将协议选择、报文构建、发送结果解释拆成独立组件，现有服务继续负责账单锁、请求幂等、逐个收件人进度与状态同步。
- 新版报文使用 `template_id`、`touser`、上述五个 `data` 字段及 H5 `page` 链接；不填小程序 AppID。字段长度、金额和日期在发出请求之前校验，缺少必要字段时给出明确错误。
- 小区名从可信小区查询获取，房屋信息和费用从指定账单读取；模板、收件人、金额、链接不接受浏览器直接指定。
- 保留已受理收件人跳过、结果不确定时禁止自动重发、发送前记录进度、支付状态保护和一分钟冷却。协议和模板纳入进度上下文，配置变更不能隐式清除未决状态。
- 订阅通知 API `errcode=0` 表示“微信已受理”，不表示业主已收到或已支付。未订阅、额度不足、拒收等明确拒绝返回可理解的提示；网络超时和不完整响应继续标记结果不确定。
- 定时旧通知路径遇到启用新版协议的账号应明确跳过旧协议发送，避免用新模板调用旧接口。自动群发不在本轮开启。

## 业主授权与页面

- 在“我的”和房屋费用查询页提供“订阅账单提醒”入口，进入一个复用的订阅界面；保持现有版式，不重新设计首页。
- 必须由用户点击微信官方组件并在微信弹窗中作出选择。不得在登录或绑定后自动视为订阅成功。
- 订阅页面使用当前登录会话及服务端解析的公众号配置获取签名和公开模板信息，不能传入可信 OpenID 或密钥。
- 服务端仅对配置的 HTTPS H5 来源和页面路径签名，签名 URL 去除 fragment，保留其余实际查询参数；不信任任意 Host、转发头或浏览器提交的其他域名。
- 服务端缓存 JSAPI ticket，仅返回 `appId`、`timestamp`、`nonceStr`、`signature`、模板 ID 及展示状态；不返回 access token、ticket、AppSecret 或 OpenID。
- 标签事件分别处理 accept、reject、cancel、filter、SDK 错误和标签不可用。浏览器成功事件只用于界面反馈及刷新，不能直接写成权威授权记录。
- 无登录或无有效业主绑定时引导完成登录/绑定；普通浏览器提示“请在微信中打开”；未配置公众号、域名或签名失败时显示可理解的配置提示。
- 页面明确说明“一次订阅可接收一条账单提醒，后续可再次订阅”，不显示长期有效承诺或未经确认的剩余次数。

## 微信回调与身份隔离

- 扩展现有微信回调，在处理普通消息和是否绑定业主之前先分发订阅事件，避免授权时尚未绑定导致事件丢失。
- 必须从服务器配置解析公众号身份并验证回调，不能以浏览器的 AppID、OpenID 或订阅状态作为依据。兼容现有明文回调模式；加密回调如未配置密钥必须明确拒绝，不能按明文接收或标为成功。
- XML 解析关闭外部实体与 DTD，并设置请求长度上限。支持同一回调多条模板记录、重复投递以及乱序事件。
- 记录按 AppID、模板 ID 和 OpenID 的摘要隔离；保存经微信回调确认的最近授权/拒收信息、来源时间及发送事件。沿用现有 Redis，不新增基础服务；记录为辅助核查状态，微信才是订阅额度和实际发送权限的权威。
- 不以回调次数估算精确的可用额度，不把重复回调算成新增授权；重复回调不重复应用，旧事件不覆盖新状态。
- 正式号 OpenID 与测试号不同。正式号启用前须重新走正式号 OAuth 与业主绑定；旧测试绑定不能当作正式号授权。通知选择仍须同时满足账单业主的已审核绑定与本公众号身份条件。
- 订阅状态查询须限制为当前已认证业主可访问的身份，不能按任意 OpenID 查询；公众号标识必须来自可信会话/配置。
- 记录中不得打印原始微信消息、用户 OpenID、凭据或含 token 的异常 URL。

## 入口与环境准备

- 网关仅开放新增签名/状态读取的确切路径与方法，继续要求入口访问校验和业务会话，不放开整个 `/app`。
- 配置正式域名时，为微信平台提供的 `MP_verify_*.txt` 文件增加精确名称匹配的静态校验路径；不开放目录遍历或任意本地文件。
- 本地配置辅助工具可输出正式号接入清单和脱敏预检结果，默认只预检。账号切换必须备份原记录，并维持同一小区唯一有效公众号，不能额外插入第二条活跃记录。
- 正式手机联调需要：可用 HTTPS 域名、网页授权域名、JS 接口安全域名、域名校验文件、通知事件回调、稳定的服务端 IP 白名单以及用户重新授权。
- 当前正式号凭据文件和测试号运行配置保持独立；此次开发不覆盖任何现有密钥或已绑定业主记录。

## 验证要求

1. 旧版通知回归：权限拒绝、无绑定、已支付、成功必须有旧消息 ID、中文 UTF-8、幂等、超时不重发、部分受理和数据库更新失败。
2. 新版通知：正确接口与五字段、日期/金额/长度校验、`errcode=0` 无 `msgid` 仍受理、明确拒绝不标已通知、非 2xx/缺 errcode/网络超时均不确定、进度上下文变更不重发未决通知。
3. 签名和状态接口：未登录拒绝、跨用户与跨公众号拒绝、跨域/非 HTTPS 签名拒绝、去 fragment、保留查询、缓存 ticket 及异常脱敏。
4. 回调：签名失败、无配置、加密报文、XML 实体、超长报文、多模板、重复和乱序、尚未绑定、拒收与异步发送事件。
5. 页面：SDK/组件成功、取消、拒绝、filter、普通浏览器、延迟会话、无配置和网络失败；合成事件不能成为后端授权证据。
6. 执行相关 Java 定向编译及 JUnit、网关与 H5 回归、H5 生产构建、本地实际 HTTP 鉴权与查询检查。真实通知和支付不在自动测试中调用。
7. 文档明确分开代码通过、本地集成通过、微信端待验证三个层次，不以模拟测试替代手机验收。
