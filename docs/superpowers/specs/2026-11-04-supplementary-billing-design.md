# 同一账期补充出账

用户已确认修复方案：已审核账单保留，新费用独立生成待审核补充账单，重复生成不重复收费。

沿用「生成待审核账单」入口和原费用计算器。当前收费项已有有效账单时，查询这一批全部账单的明细，排除已出账的 feeId（包括待审核、已通知、已缴费），只计算剩余费用；无新增可出账费用返回已有账单。补充账单仍为 DRAFT，不自动审核或通知。

同一收费项允许一张原账单及多张补充账单同时为当前账单。最早当前账单作为账期锚点，补充生成不推迟原滚动周期；进入下一周期时，原有整批账单按既有逻辑转历史，新账单重新计算。已发布的金额、明细、通知状态和时间保持原值。

保存事务锁收费配置行，然后重新核对账期锚点及已出账 feeId，阻止并发重复。补充写入不执行旧的整项目历史化操作；普通跨期生成仍执行。在 bill 表新增可空 base_bill_id：原账单为空，补充单固定关联原账单，避免同秒出账时随机编号影响账期识别。迁移只新增该字段，并核验原账单全部已有字段内容不变。

人工托收和缴费状态回写按 feeId 查询整个当前批次，不能继续只读最新一张汇总。并发保存冲突或未知结果，只有确认本次尝试的全部费用已落在同一张有效账单内时才返回该账单；无法确认则重算或明确失败。

验证覆盖：已发布和待审核之后新增费用、连续多次补充、重复操作、并发、已通知/已支付排除、跨期重建及明细写入失败回滚。使用随机隔离数据验证真实后台和 H5 查询；不向真实业主发送测试通知，不启动定时任务，不收款。更新服务前备份原包及数据库，构建完成后才重启，缩短查询中断。
