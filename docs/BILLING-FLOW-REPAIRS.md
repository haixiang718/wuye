# 账单流程修复说明

日期：2026-11-02。对应分支：`codex/billing-flow-repairs`。

本轮本地复测通过：公开注册、审批登录、真实出账、待审隐藏及禁止通知、后台按钮审核发布、已发布账单查询、同账单模拟通知与重复请求防重、H5 详情和欠费页。测试资料清理后，15 张原有业务表的行数及摘要恢复。六 Java 服务及管理后台已恢复运行。

本轮修复来自[全流程诊断](BILLING-FLOW-SIMULATION.md)，真实微信支付继续关闭。支付回调测试使用独立进程和随机隔离测试库，不向运行中的支付通知接口发送伪造回调。

## 当前业务规则

1. 物业先录入业主、房屋及收费资料；新用户通过 H5 注册并申请绑定，经物业审批后登录查看自己的房屋。微信授权识别微信身份，不自动赋予任何房屋权限。
2. 出账生成固定金额与账期的账单，初始状态为 `DRAFT`。物业在“账单管理”查看明细后点击“审核发布”，状态变为 `PUBLISHED`，记录审核人、时间及意见。重复审核不会覆盖原审核记录。
3. 已发布账单可在 H5 查询；物业在账单明细中另行点击“推送账单”。审核发布本身不发送通知。旧定时通知也只能选择已发布账单，当前自动任务保持关闭。
4. 通知状态与审核状态独立：通知受理后的 `3000` 仍是未缴费，可继续查询。微信接口受理消息不等同业主收到或已支付。
5. 支付开通后，服务端从已发布账单生成可信订单，不接受浏览器自行提供的金额或账期。回调核对签名、公众号、商户、订单、金额和交易号，同一事务写缴费流水、收据、实收金额并销账；成功提交后才应答成功，失败可重试，重复回调不重复入账。这里的入账指物业费实收与缴费流水，不是业主储值充值。

## 修复内容

- 匿名注册转发使用服务端默认身份，清除大小写变体的伪造身份头；已绑定房产和小区权限继续校验。
- 居民费用及欠费接口只返回已发布、仍欠费的账单快照，固定账期和金额；旧停车收费参数接口对居民关闭，保留员工停车集成查询和已缴费历史。
- H5 欠费页修复重复加载、未定义方法、累计金额和异常处理。详情页重新核验具体账单，未发布、已支付、失效或身份不匹配时禁止付款。
- 支付三个下单入口默认由服务端关闭，不能通过绕过 H5 按钮启用。
- 新增持久化支付订单、明细关联和费用占用记录，保护重复下单、并发通知和跨账期未完成订单。订单复用逐项核对快照，微信支付身份限定当前用户、小区、应用类型及已审批绑定。
- 删除支付回调原文及包含商户密钥的签名调试日志。
- 显式注册网关支付 Feign 客户端，修复实际启动缺少 Bean 的集成问题；本地迁移或启动订单服务后刷新应用路由缓存，修复新增审核接口已登记但提示无权限的问题。

## 数据库升级

只对本机隔离实例 `127.0.0.1:13306/TT` 执行。本轮没有修改其他 MySQL 实例。

```powershell
python scripts/migrate_bill_review.py          # 只查看计划
python scripts/migrate_bill_review.py --apply  # 完整备份后应用
python scripts/migrate_payment_order.py
python scripts/migrate_payment_order.py --apply
python scripts/local.py migrate               # 注册本地审核路由
```

升级新增账单审核四列、查询索引、三张支付表和旧收据缺失的两个付款对象字段。迁移先检查兼容性、完整备份，再执行新增操作；重复运行不重复修改。备份和校验报告仅在忽略的 `.runtime/backups/`。`local.py migrate` 在订单服务已运行时同步刷新应用路由缓存；订单服务启动后也会刷新，新增路由不会继续使用旧缓存。

旧账单默认待审核，需要物业核对后发布，不自动推送历史欠费。

## 验证边界与后续接入

定向测试包括注册与房产权限、审核及通知门槛、H5 页面、微信 V2 回调替身、真实 MyBatis SQL 与事务回滚/并发，以及迁移备份和幂等；详细结果见 [本轮验证记录](validation/2026-11-02-billing-flow-repairs.json)。全量 Maven 打包使用 `-DskipTests`，测试由定向脚本独立执行，不能把打包当作测试。

真实商户接入、API V3、主动查单、平台对账、退款及已确认关闭待支付订单尚未验收；不得据此开启正式收款。待支付订单不能因缓存过期或超时自行释放。跨月旧订单支付后，如果新一期快照仍包含旧欠费，系统会安全拒绝不一致的新付款，需要后续重新出具一致账单与对账流程，见[支付订单约定](PAYMENT-ORDER-CONTRACT.md)。

本机流程复测使用随机测试资料和真实本地业务服务；公众号身份及外发为替身。真实支付 SQL 在独立随机测试库验证并清理，未向 TT 注入伪造支付。正式公众号、微信商户、外网域名与手机收件需单独联调。
