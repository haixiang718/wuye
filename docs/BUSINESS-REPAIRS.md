# 业务修复记录

日期：2026-11-02。分支：`codex/business-fixes`，基于 `3313a67`。本轮针对已复现的账单生成、业主绑定权限及后台合同查询问题；沿用七业务模块合并部署，不涉及正式网关部署或微信支付开发。

## 账单生成

保留现有月费、面积、预付/后付、缴费周期和累计欠费计算方式。账期仍是原有的向前滚动日/月/年窗口；客户尚未确定每月出账日，未改为自然月计费，也未启用定时出账或自动通知。

- 任务服务先计算某个收费项的全部明细，任何一笔费用计算或房屋/业主查找失败即中止该收费项，避免部分成功、伪造业主和孤立明细。
- 新增 `saveBillSnapshot` 内部接口，在费用服务的单一事务中保存汇总与明细，任何数据库写入失败全部回滚。
- 事务内锁定真实收费配置行，再检查当前账单、滚动周期和上一账单版本。并发调用只接受一批，类型 005 同样受月度防重保护。
- 切换当前账单标记时同时限定收费项和小区，保留历史账单时间。明细金额先按分四舍五入再汇总。
- 不自动修改历史异常账单。此前失败遗留的数据需要逐条确认归属、通知和缴费状态后再处理。

验证分为三层：原业务计算与边界替身、真实 Spring 事务与生产 MyBatis SQL、真实本机 HTTP 服务及独立数据库。数据库事务测试使用随机测试表；HTTP 测试只创建随机标识收费项及 0.01 元费用，结束后按精确标识清理，不修改既有业主和账单。

## 业主注册、绑定及权限

自行注册、新增绑定统一保存为 `10000` 待物业审核，忽略客户端提交的“已通过”状态。已有 `12000` 绑定保留。密码登录、OAuth 自动登录和授权票据交换仅接受审核通过的绑定；待审核时明确提示联系物业。

同一账号可以绑定多个业主身份；同一业主身份关联多套房产时可查询各套房屋。新增绑定的查重条件使用服务端登录用户、实际查询得到的小区和成员，不再直接采用客户端传入的身份条件。注册时不接受任意 OpenID，微信身份须由经过验证的授权票据建立。

front 的 `/app` 转发入口新增服务端权限校验：

- 从真实会话取得用户，覆盖客户端伪造的用户请求头。
- 绑定列表仅返回当前用户，解绑仅允许自己的绑定。
- 房屋、车辆、车位限定到当前用户在指定小区审核通过的业主身份；家庭成员沿用数据库投影出的实际业主 ID。
- 房屋使用家庭业主 ID，车辆/车位使用绑定成员 ID，兼容家庭成员独立持有车辆。车辆查询只转发必要字段，车主姓名模糊搜索在列表与计数 SQL 中均改为 JDBC 参数绑定，避免搜索表达式绕过归属条件。
- 费用必须归属于上述房屋或车辆；费用历史、优惠查询先核实费用实际归属。
- 优惠查询的付款对象从已核验的费用记录取得，覆盖客户端传入的另一房产或车辆标识。原有匿名短信和微信照片注册入口保留，注册业务仍负责校验信息及进入待审核状态。
- 普通业主不能通过修改客户端 AppID 调用后台管理接口。
- 兼容历史普通用户级别的管理账号：根据数据库中有效商户关联确认其身份，并继续执行原有后台权限校验。

本轮针对保留 H5 查询和绑定入口。支付下单、真实微信授权、手机上新增绑定及审批的完整操作仍需业务验收，不能用模拟接口测试代替。

## 合同与账户

资源型接口曾生成 `/api//contract/queryContract`，已规范 front 转发路径，兼容以 `/` 开头的服务名，不新增重复服务路由。但合同失败的主要原因不是路由丢失：真实商户范围返回的 404 业务码包装了下游数据库 500，具体缺少 `contract_parent_id` 等字段。原来的空测试商户查询只走数量分支，未执行详情 SQL，不能证明合同查询成功。

当前 `contract` 相比映射器缺少 `b_id`、`contract_parent_id`、`obj_name`、`obj_person_id`、`obj_person_name`、`start_user_id` 六个字段，列表查询及部分写入均受影响。仓库现有 SQL 同样未提供对应升级定义。

账户模块的数据库阻塞尚未解决：独立库 `TT` 缺少 `account`、`business_account`、`account_detail`、`business_account_detail` 四张表。仓库中可用的是 0.6 商业版 SQL，与 0.8 代码存在差异；已检索的 SQL 中没有这四张表的建表定义。直接账户查询目前仍返回 500，不能宣称账户功能已修复或全部保留业务可上线。

需要取得与当前版本匹配的原始建表/升级脚本或原系统数据库结构备份，再备份本地库、审核迁移、验证账户及交易明细读写。用户已确认目前暂时拿不到这些脚本，因此这两个模块保留为阻塞项。不能根据 Java 字段猜测金额精度、约束和流水结构后直接投入财务使用。
