# 后台、H5 性能与安全检查

日期：2026-11-06。本轮针对当前物业收费版本进行源码审查、合成接口测试、隔离 MySQL 验证和静态资源测量。没有代用户付款、退款、发送通知，未删除业务表或真实财务记录。

## 已修复的问题

| 问题 | 修复及验证 |
| --- | --- |
| 旧 V2 回调未区分 V3 订单 | 回调只接受明确的 V2 订单；正确 V2 签名也不能确认 V3／缺失版本订单。46 项回调检查通过。 |
| 公共公众号配置接口按客户端 AppID 决定是否返回密钥 | 公共 front 出口无条件清除 appSecret、payPassword 等字段，异常响应安全失败；内部支付服务保留内部查询。修改客户端标识不能改变此规则，51 项权限检查通过。 |
| 旧退费申请／审核只改流水，不执行微信退款 | 服务端关联收据、账单快照及已入账订单，拒绝在线支付流水进入旧退费和直接编辑流程；不信任客户端支付方式或备注。3 项监听器验证及数据库用例通过。 |
| 人工收费与微信待支付订单可能重复收取 | 人工明细写入、费用修改、批量写入使用同一费用行锁并检查支付占用；线上下单也检查同账期已收明细。验证先线上／先线下两种并发顺序，后到路径拒绝。40 项支付数据库检查通过。 |
| 17 个 Mapper 的 41 处搜索词直接拼入 SQL | 改为参数化 LIKE；真实 MyBatis 渲染和 JDBC 绑定覆盖 328 次输入，隔离 MySQL 收费查询另做 12 次实际执行检查。 |
| 事务日志把绑定值重新拼成 SQL，特殊字符可破坏 SQL／回滚 | 使用 SQL AST 和原 MyBatis 参数映射查询旧值；补偿值按明确类型编码，标识符验证，空值使用 NULL-safe 条件，兼容旧日志。隔离库验证修改、删除、批量插入、INSERT SELECT 和三种补偿。 |
| 静态目录链接可能暴露根目录外文件 | 真实路径校验，越界链接返回 403，包含二进制及 Range 兜底路径；Windows junction 测试通过。 |
| 未登录错误页返回内部路径及堆栈 | 统一只显示 HTTP 状态短语、禁止缓存；公网不存在路径已验证 404 且无内部路径。 |

支付金额仍以数据库发布快照为准；订单归属、通知验签、重复入账保护、查单补偿和试点限额继续保留。V3 业务流程的 101 项离线检查通过。真实支付历史没有被重放或关闭。

退费保护是禁止不完整的旧流程修改在线流水，**不是已经实现微信退款**。当前表结构没有独立的订单到流水外键，保护采用收据、费用、账期及金额的保守关联；极端相同数据可能需要财务人工核实。同一账期已经有正额线下实收时，线上下单拒绝并提示核实，不自动扣除未知部分付款继续收款。

## 性能与技术债

- 两个前端源站增加静态文本 gzip、条件请求和有界压缩缓存。哈希 JS/CSS 可在已通过访问门禁的浏览器私有缓存；HTML、配置、接口和错误响应不使用长期缓存。
- 同条件本机浏览器测量：后台冷加载资源传输 2,295,071 → 736,049 字节（约减少 68%）；H5 冷加载 1,233,248 → 438,823 字节（约减少 64%）；H5 再次访问 1,232,948 → 63,495 字节（约减少 95%）。后台原有再次访问的条件缓存仍有效，HTML 明确不缓存后该项传输略有增加。
- 公网 Nginx 原本已经启用 gzip。上述数据代表源站和 SSH 隧道侧资源传输，不是公网手机延迟、并发容量或同等比例的速度承诺。详见 [静态测量](2026-11-06-static-performance.json)。
- 在完整 96,099,247 字节备份后新增 7 个非唯一查找索引；相关表行数、内容校验值不变。账单编号、房屋费用、字典查找从 ALL 改为 ref；没有删除旧索引或更改业务唯一性。详见 [索引验证](2026-11-06-billing-indexes.json)。
- 更新后台兼容安全补丁，移除 Express 示例路由、三个 Jade 模板及 47 个依赖包。后台生产依赖 npm 公告从 19 项降为 0。发布包构建同步包含新的静态中间件，避免只在开发目录可运行。

## 数据库盘点

TT 327 张表，hc_community 65 张表，共 392 张。364 张发现代码／配置／框架依赖，4 张历史备份表，11 张疑似废弃空表，13 张需要确认。分类不是删除授权；空表仍可能是未发生业务的必要结构。

较大的 transaction_log_message、application_key、u_user_login 均有使用依据，不宜直接删除。每张表的大小、行数、源码及动态 SQL 引用、索引见 [数据库盘点](2026-11-06-database-inventory.md) 和配套 JSON。

## 验证边界与后续工作

- H5 的旧 uni-app／Vue 2／构建依赖仍有 106 项 npm 公告，不能因为只查生产依赖时为 0 就宣称浏览器安全。后台 public/js 中手工附带的库和 Java 依赖还需单独升级审计。详见 [依赖报告](2026-11-06-node-dependency-audit.md)。
- 内部通用 SQL、回滚及旧存储过程接口仍以本机绑定／内网和网关路由隔离为边界；当前未启用的过程配置不能直接作为新功能开放。跨主机正式部署应补充服务认证并复核防火墙。
- 补偿继续保留原有全局事务协议和乐观匹配。当前支持单表更新、删除、明确列的批量 VALUES 和 INSERT SELECT；多表更新、upsert 等未支持结构会拒绝。非确定性表达式、自动更新时间、数据库触发器和跨事务并发修改仍需专门验收，本轮没有宣称重建了一套完整分布式事务系统。
- 真实微信退款、平台账单对账、全量收款开放及生产并发容量不在本轮验收结论中。没有执行公网压力攻击或对真实财务数据做注入。

可重跑入口：`scripts/security/run_mapper_parameter_binding.py`、`scripts/security/run_rollback_sql_security.py`、`scripts/tests/run_payment_order_database_java.py`、`scripts/tests/run_online_payment_refund_guard.py`、`scripts/simulation/run_payment_audit.py`、`scripts/tests/run_wechat_pay_v3_flow.py`、`scripts/tests/run_owner_access_java.py`。使用 `.runtime/billing-audit` 的 Java 检查须串行运行；数据库盘点默认只读，索引迁移默认只列计划。

## 部署结果

12 个 Maven 模块打包成功，更新 order、business、api、front、job 及三个 Node 入口，保留旧 JAR 回退目录。最终 21/21 健康检查通过；真实财务相关六张表的校验值与更新前一致。已通过只读接口确认真实 0.01 元试点流水被新保护识别，没有触发退费；空账单选择仍在业务入口被拒绝。

后台 65 项、H5 128 项、静态与网关 7 项 Node 测试通过；微信 SDK 18 项、权限 51 项、支付数据库 40 项、旧回调 46 项、V3 流程 101 项、退费入口 3 项检查通过。索引迁移 3 项，发布／运维 24 项通过、1 项环境限制跳过。编译 H5 的两个浏览器检查覆盖 360／390／430 像素，包含首页裁剪、金额、历史、选择支付及空选择／失效选择，均使用模拟接口。

公网 H5 哈希资源已确认 gzip、private immutable 且解压后与本地构建字节一致；管理端错误页不含内部路径。源码变更检查未发现当前本机运行密钥被带入本次提交。部署摘要见 [security-deployment.json](2026-11-06-security-deployment.json)。
