# 正式号账单模板适配

日期：2026-11-03。正式号已添加“物业费用账单缴纳提醒”。保留现有后台人工推送按钮，不新增另一套通知入口。

| 模板字段 | 系统数据 |
| --- | --- |
| 业主姓名 thing2 | 账单业主姓名快照，不能用房屋名称替代 |
| 账单金额 amount4 | 当前审核账单冻结的待缴金额，两位小数 |
| 缴费类型 thing9 | 费用类型名称 |
| 账单名称 thing10 | 收费项目名称，缺少时使用费用类型加“账单” |
| 提醒时间 time12 | 本次通知时间，Asia/Shanghai |

thing 文本按 Unicode 字符最多保留 20 字，完整内容仍在 H5 详情。缺少姓名、类型，或模板不属于当前公众号、字段含义不匹配时拒绝发送。发送前通过微信只读接口核对所选模板；接口未声明字符集时显式按 UTF-8 解码。原 first/keyword1/keyword2/keyword3/remark 格式继续支持，不支持的字段不会盲发。

配置仍位于当前小区公众号的“欠费推送模板”（属性 33002），已备份旧值后定向更新为正式号新模板 ID。仅修改该配置，没有改账单金额、通知状态、缴费状态或绑定关系。备份与模板列表位于忽略目录 `.runtime/nonpayment-readiness`，不分享密钥或业主标识。

本轮验证：32 项人工通知 Java 回归、8 项只读工具测试通过；包含草稿/已缴费拦截、权限、防重、未知结果保护、新版字段、北京时间、长文本、缺失姓名及无 charset 中文响应的回归。首次实际接口只读探测复现了解码错误，修复后重新构建 API，从最终 JAR 提取代码和依赖，再调用正式模板列表并生成五字段数据，验证通过。真实手机收件不由这些测试替代，尚未向任何业主发送本轮消息。

手机验收：指定已关注正式号、且在正式号 H5 完成授权及物业审批绑定的测试业主。在后台选择其已审核发布且有待缴金额的账单，人工点击“推送账单”；核对收件、内容、点击后正确房屋及其他账号不能访问。微信接口受理不等于手机已收到，通知也不等于已支付。

这是模板消息，不需要每条通知都重新进行一次性订阅；后续可用于符合业务和平台规则的月度账单提醒。当前自动出账/通知任务仍关闭，原定时发送器未做本次五字段改造，不应直接启用。支付未开通，继续保持关闭；既有 Linux 发布准备包为此前快照，正式部署前须从选定提交重新构建。
