# 支付方式字典修复（2026-11-03）

## 问题与原因

“房屋收费 → 欠费缴费 → 收费确认”的支付方式只有占位项。真实浏览器复现时，`/callComponent/core/list?name=pay_fee_detail&type=prime_rate` 返回 HTTP 200 和空数组，页面没有脚本错误。当前本地导入的旧数据库缺少 `t_dict` 中这一组数据，样式和接口路径正常。

同一组字典也用于普通缴费、缴费记录筛选和报表中的支付方式名称。修复数据库配置比在单个页面硬编码选项更完整。

## 配置与语义

| 编码 | 名称 | 使用方式 |
| --- | --- | --- |
| 1 | 现金 | 人工登记已收到的现金 |
| 2 | 微信（线下已收款） | 人工登记已核实的微信收款 |
| 3 | 支付宝（线下已收款） | 人工登记已核实的支付宝收款 |
| 4 | 银行卡/POS（线下已收款） | 人工登记已核实的银行转账或 POS 收款 |
| 5 | 微信小程序支付 | 原程序保留的实际小程序支付渠道 |
| 6 | 微信公众号支付 | 原程序保留的实际公众号支付渠道 |

1–4 为本地补充的人工收款配置；现有程序没有为这几个编码提供支付网关调用分支。5/6 的含义由后端 `PayFeePreListener` 确认，原缴费页面主动排除这两个选项，因此补齐后后台仅有 4 个可选项。选择方式不会发起微信或支付宝扣款；点击“确定收费”会沿用原逻辑登记收费。公众号在线支付仍需独立完成商户接入。

没有修改缴费业务代码，也没有设置默认支付方式。

## 执行和部署

```powershell
python scripts/migrate_payment_methods.py
python scripts/tests/test_payment_methods_migration.py
python scripts/migrate_payment_methods.py --apply
```

第一条只查看计划。`--apply` 仅支持本机 `127.0.0.1:13306/TT` 或指定格式的临时验证库：先验证结构，完成整库备份后，在单次事务中插入缺失字典。已有名称和其他字典不被覆盖，重复执行不添加重复记录；遇到同码重复配置、缺失列、非事务表或备份失败会停止。共享本地迁移锁避免并行迁移。

该脚本不是远程部署工具。部署到其他服务器时，应在目标环境按上述表核对、备份并补充缺失字典，不将本机脚本直接指向远程生产库。

本次执行新增 6 条字典，整库备份位于本机 `.runtime/backups/payment-methods/TT-20261103-112536-befbae56/before.sql`。备份文件和浏览器会话不提交 Git。
