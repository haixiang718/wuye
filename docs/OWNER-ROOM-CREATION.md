# 新增业主并绑定房屋

入口：<https://admin.jiaanfuwu.cn/> → 业主管理 → 业主信息 → 添加业主。本机后台也使用同一页面。

1. 填写姓名、性别、手机号、身份证等资料。
2. 在“绑定房屋”区域输入楼栋或房屋编号，点击“查询可绑定房屋”。
3. 勾选一套或多套房屋；翻页保留选择，下方清单可以移除。一次最多50套。
4. 点击“保存”，系统在同一次订单中创建业主、建立全部房屋关系，并同步房屋状态。

房屋应先在系统中建档，并属于当前小区、尚未绑定其他业主。选择房屋时，姓名、手机号、身份证必须填写完整，供业主在微信端核验。相同身份证已有档案时，系统提示使用原业主的房屋绑定功能追加，避免重复录入。也可以不选择房屋，仅保存业主资料。家庭成员、租客的添加页面保留原用途。

提交期间按钮和表单锁定。参数错误、房屋已绑定或请求失败时保留资料，便于修正后重新保存。遇到网络超时，先查询业主列表确认结果；不要把网络错误当作确定未保存。微信身份认领仍通过姓名、手机号、身份证三项匹配完成，此处录入不会替业主完成微信授权。

## 实现与运行

复用现有 addOwner/saveOwner → owner.saveOwner 及订单业务，支持 roomIds 数组。前置层使用登录员工所属物业并检查房屋绑定权限；API校验身份、当前小区及房屋可用性，提交时锁定身份和房屋后重新核验。新入口、原单房创建和原房屋绑定共用房屋锁。关系写入有效起止时间，房屋状态更新与原绑定流程一致。未增加数据库表。

未绑定房屋查询补齐了楼栋号；选择器按既有接口的 total（记录数）、records（页数）展示分页，兼容空列表省略 rooms 的旧响应。

已备份数据库和更新前的服务包，并构建更新 API、front、合并业务服务。当前公网入口仍依赖本机业务及隧道在线，恢复方式见[入口运行说明](../deploy/ingress/README.md)。

## 验证与边界

前端64项测试（新增录入17项）、Java多房创建13项和原业主访问44项通过。公网浏览器验证、真实SQL核对及清理记录见[本次验证](validation/2026-11-04-owner-room-creation.json)。

实际测试使用随机隔离资料，验证一次保存一名业主和两套房屋，重复/无效/已绑定组合被拒绝。另通过超长属性触发真实订单暂存阶段失败，再用同一身份和两房正常保存，确认失败未留下有效业主或房屋关系。未注入实例转换完成后的进程崩溃，不将这项验证描述为所有分布式故障均已验收。

隔离资料已清理；15张原业务表行数及内容摘要一致。浏览器访问可能轮换原账号的临时会话密钥，该技术登录元数据不回退；订单审计记录保留。未发送公众号消息、未收费。
